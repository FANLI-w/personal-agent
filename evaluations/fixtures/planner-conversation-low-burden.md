# Input

合成对话场景：“我之前做过一个研究项目，投稿以后还想进一步完善。”没有提供论文内容、评审阶段、下一轮投稿去向、参与人或日期。

# Expected behavior

- 先承接已有研究，给一个有根据的小切入口，用短段落直接交流。可以先聊研究本身或目前卡住的一点，不从填项目表开始。
- 确实需要信息时，一轮最多一个能用一句话回答的简单问题；不能把研究方向、评审阶段、完善类别、优先级、后续去向和日期合成一项或列成长串选项。
- 未知日期、成员和资源继续未知；已经说过的信息不重复问。用户说“不知道”或“问题太多了”时降低回答负担，给一小步帮助。
- 用户提供足够清楚的下一步或要求方案后，再用已有拆解方法；不强迫每轮生成任务表，不冒称已理解未提供的稿件或已执行实验。
- 使用现有Plan接口。草案可以零步骤，当前一段交流保留在至多一个待澄清项；不能新增未定义字段或自动确认正式任务。其他旧版待定信息不因聊天显示调整而被删除。
