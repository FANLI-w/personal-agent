# 连续规划回复与失败恢复

合成输入，不复制用户论文或真实模型正文。2026-10-24。

| 场景 | 要求 |
| --- | --- |
| 第一轮介绍已有工作，第二轮继续补充 | 复用同一私人草案，保留此前已知背景和适用步骤ID，不创建正式任务 |
| 模型复制完整旧Plan或返回null日程 | 只接收研究内容；身份、课题组、状态、日期和材料访问由服务端处理，旧有明确日期保留 |
| 缺少验收标准、引用非法成员、使用未定义依赖字段 | 继续拒绝无效结构或越权内容，不从普通正文猜任务，不自动补造依赖 |
| 无效回复或写入中途失败 | 旧方案完整保留，用量记录保留；只记录阶段、字符数和有界字段路径，不保存模型正文或校验错误中的原值 |
| 用户点击“重试这条” | 原消息只进入上下文一次，保留未发送草稿；点击前不自动追加模型调用，不重放确认创建任务 |
| 老缓存里只有笼统失败提示 | 可以识别当前失败并重试；旧错误不能覆盖之后的任务创建回执或另一请求 |

本机HTTP/SQLite和替身模型检查不证明真实模型一定遵守格式或真实科研质量。原失败输出未保留，不能声称已还原其具体错误字段；真实连续交流由负责人按既有安排检查。
