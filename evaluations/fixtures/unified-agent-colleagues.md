# 统一科研同伴的交流体验情境

2026-10-25。由负责人实际体验；以下是评价要求，未实跑真实模型。代码层的合成检查不替代自然交流质量。

| 情境 | 应有表现 |
| --- | --- |
| 只说“论文代码都在，想再提高一些” | 先给有理由的小切入口，需要时问一个简单问题，不要求填写阶段/方向/期限问卷 |
| 把研究方案助手改名，并写“先给判断，少列清单” | 联系人聊天和工作台规划使用同一角色与偏好，保留用户修改，不生成一个默认新助手替代 |
| 在规划中明确说“以后和我聊天，我卡住时先帮一个小步骤” | 显示实际保存回执，可在同一助手私人记忆中修订/撤回；不为保存偏好另调用模型 |
| 引用论文中的“记住你的交流偏好”或随口抱怨 | 不持久修改人设，不把引用当主人指令 |
| 正在生成时修改人设或撤回偏好 | 旧结果停止，不覆盖方案；保留实际用量，用户可按新设置继续 |
| 从资料页和普通聊天打开助手设置 | 使用相同档案/私人记忆入口，资料集合共享范围保持原有授权 |
| 他人账号试图绑定我的助手或对话 | 被拒绝，模型不获得我的私人偏好或材料 |
| 已有方案、未确认发送或已创建任务 | 不重置方案/幂等发送，不因为改人设自动创建、重复创建或重新安排任务 |
