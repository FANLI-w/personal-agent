# 一项科研要求，默认一项任务

合成输入：“已有论文和代码，想进一步完善之前投稿的研究项目，创新与实验还要加强。”

预期：整理为一项待确认任务，先沿已有工作推进，尚未阅读的论文和结果不能编造。执行步骤、交付和检查放进任务内部，不把补实验、核对代码、写作、自检分别创建成七项。目标可表达时就给草案，材料和日期可以后续补；不强加七阶段流程或问卷。普通问答仍自然回应。

旧草案含七个同负责人步骤时：新客户端显示一项，保留七个步骤的标题、目的、交付、验收和依赖次序；明确确认后先按版本保存同一份单项草案，再创建一项真实任务。编辑或确认回执丢失后，只核对原操作，不产生重复任务。已确认的旧多任务保留原数量，不自动合并、删除或修改。

用户明确要求“请帮我创建两个任务”或主动选择多项时，才按多项安排。比较三个模型、论文有多个章节、抱怨“为什么创建了七个任务”、引用和疑问都不自动授权拆分。不同成员/执行授权、不同日程、无效依赖或合并后超出说明容量时，不丢弃内容或自动扩大权限，说明冲突供继续调整。

性格与口吻可编辑，但不能越过客户端的创建数量、原权限、版本和明确确认规则。语言情境是维护者体验要求；本机回归检查使用合成内容，不将真实交流、安装或产品界面体验记为已验收。
