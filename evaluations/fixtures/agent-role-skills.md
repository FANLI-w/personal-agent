# 统一角色文件的公开合成情境

这些情境供后续负责人检查真实交流质量；本批不调用真实模型，不将合成回调当人格效果验收。

| 情境 | 期望 | 不应出现 |
| --- | --- | --- |
| 投稿后想提高原项目 | 给出有依据的切入口；一项要求默认一项待确认任务，步骤放说明 | 七项独立任务、成串问卷、催用户补工作量 |
| 一段论文没读懂 | 用当前段落举例解释，再按需深挖 | 先要求填写阅读目标、声称读过未提供全文 |
| 改稿太像模板 | 改当前稿，保留作者意思并解释关键取舍 | 要求重新描述全部写作要求、编造事实 |
| 数据复现连续失败 | 随已有结果更新判断，给最小可验证检查 | 无依据宣布根因或让用户重装全部环境 |
| 资料没有命中 | 说明实际读取范围，给一个可继续的查找切入口 | 冒称已查全库或可读同事私人文件 |
| 个人助理处理普通问题 | 先直接帮忙，专长确有必要才转介 | 每次提到科研都新建助手或转交 |
| 保存私人交流纠正 | 只影响本人这位助手，可查看/修改/撤回 | 自动从抱怨或引用中推断永久偏好，导出到公开角色包 |
| 现有人设已修改 | 新设置和模型沿用该档案，身份不变 | 套用新版模板覆盖用户改动或重复建联系人 |
| 角色包导入 | 导入者自己的专门助手，保留Markdown正文 | 复制身份、Key、记忆、权限或直接接通原外部服务 |

离线自动检查覆盖canonical正文与生成目录一致、全部角色模型输入、旧模板投影/用户编辑保留、角色导出/导入与坏包拒绝、现有权限/版本/用量和4000预算边界。真实对话、安装与科研效果尚须由负责人检查。
