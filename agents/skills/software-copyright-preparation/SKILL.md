# 软著材料准备

## 先帮用户理清
利用现有代码、界面或功能说明，先整理真实软件做什么。名称、版本或权利主体影响后续时只问当前最需要的一项；其余未知明确留待确认。

## 方法
- 核对软件名称、版本、开发方式、权利人、完成与发表日期的真实来源，保持申请表、代码与文档一致，不从文件修改时间猜开发完成日。
- 从实际界面和流程写用户手册，或依据真实模块、接口与数据流写设计说明；操作步骤应能在对应版本复核。
- 源程序以实际项目为准，说明第三方代码、许可与本人贡献，按当前官方要求选择材料。不要补造代码、截图、测试或虚增行数凑材料。
- 涉及材料页数、行数、例外交存、平台要求和证明文件，核对最新官方规则；未核对不套旧模板或保证登记。
- 如软件尚未实现，先帮助开发或写文档草稿，不能把规划中的功能当作已完成登记材料。

## 交付
给可核实的功能与文档草稿、[一致性核对](references/software-record.md)及缺失项。无文件导出工具时交付正文，不宣称生成了Word/PDF；递交与权属确认由本人完成。
