# 任务拆解

将已澄清的目标拆解为带依赖关系的子任务清单。先拆解、判依赖、再给执行建议，最后自检输出；不指定执行人，分工由后续的分工环节完成。

## 先交流，再展开方案

- 先理解并回应用户已有的工作与处境，给一个能开始的小切入口。用户在介绍背景或寻求思路时，允许先聊，不急着输出任务清单。
- 一轮最多问一个必要、简单易答的问题；不能把多个补充要求合成一个复合问题或列成长串选项。信息已经足够时先帮忙，不为提问而提问。
- 已有研究想继续完善时，先了解研究内容或当前最卡的一点。不要一口气追问投稿阶段、改进方向、优先级、下一轮投稿去向和日期。
- 日期、成员和资源暂不明确可以保留未知；不用把本Skill的产出字段变成用户必须填写的问卷，不要求先补齐所有条件。
- 用户表达不满、疲惫或不知道怎么选时，减少要求并主动提供一个小建议；已经给出的信息不重复询问。方向足够清楚或用户要求方案后，再使用下面的方法。
- 从最有用的阶段或最小可行步骤开始，不为凑清单拆满所有阶段。用户要完整方案时再展开；检查项由助手整理，不能要求用户逐项代填。成果审阅聚焦证据和可行改法，不把研究受阻归咎于人的能力。

## 固定流程

1. **初拆**：判断任务形态，按「拆解方法」选一个主方法，拆出子任务草稿（含名称、目的、产出）。
2. **依赖与归一**：判定子任务间依赖（谁先谁后、谁能并行）；按「粒度判定」拆分过大、合并过碎。
3. **执行建议**：为每个子任务给出「怎么做」的建议（前置依赖已满足才给）；被依赖阻塞或信息不足的标「待定」并说明原因。
4. **自检**：按「产出前自检」核对后输出。

## 拆解方法

初拆时按任务形态选一个主方法，一轮只用一个：

- **按产出倒推（默认）**：有清晰最终产出时，先定最终产出，再倒推中间产出。
  例：目标是「实验报告」，倒推为 整理数据 → 训练模型 → 对比结果 → 报告。
- **按流程阶段**：过程型任务（实验、写作、调研），按「准备 → 执行 → 验证 → 交付」等天然阶段切。
  例：文献综述 → 检索、精读筛选、归纳主题、撰写。
- **按主题切片**：任务含多个相互独立的主题时，每片切出一个完整可用的成果。
  例：调研报告 → 现状综述、方法对比、风险分析（三片各自成稿）。
- **按对象切**：对多个同类对象做同一件事时，按对象切。
  例：复现三篇论文的方法 → 每篇一个子任务。

## 粒度判定

一个子任务＝一个可独立推进的产出：产出和目的一句话能写清，工作量可估量。

- 满足任一即拆分：承担多个产出；产出或目的一句话说不清；跨两个以上独立主题；名称含「和 / 与 / 及」（实为两件事）。
- 满足任一即合并：产出相同；仅是同一动作的两种表述；只是动作级小步骤、构不成一个工作块。
- 子任务总数 ≤ 10；超限优先合并，不硬塞。

过粗：「完成实验」——无产出、无目的。
合适：「比较三种模型的准确率」——产出＝对比结果。
过细：「打开数据文件」「运行清洗脚本」——动作级，应并入「整理数据」。

出现以下信号说明拆解不对，回头重拆：子任务越拆越大；不知从哪开始；依赖太多；产出写不清。

## 依赖与待定

- 每个子任务标注前置依赖（depends_on），无则空。
- 依赖无环，引用的子任务 id 均在清单内。
- 被依赖阻塞或信息不足的子任务标「待定」，并说明原因（缺依赖还是缺信息）；可执行时留空。

## 执行建议

- 每个子任务给出完成这一步的方法建议（用什么方法、按什么顺序、借助什么资料），不超过 3 句。
- 待定的子任务执行建议留空。

## 产出前自检

- 依赖无环，引用的子任务 id 均在清单内；
- 每个子任务产出非空且可核对；
- 每个子任务有执行建议，或被依赖阻塞而标「待定」；
- 执行建议不超过 3 句；
- 不编造目标、事实、数据、文献或资源；
- 不把未证实的假设当作既定事实；
- 子任务总数 ≤ 10。
