# AcceptCat 角色文件

所有默认 Agent 角色的唯一内容来源。研究方法仍放在 [agents/skills](../skills)，角色包不混入科研方法列表。

组织方式参考 [Distilly](https://github.com/titanwings/distilly/tree/0afc45c29c360ba7bc8260f1bb0bf34e9155f4fa) 的 Persona + Work + Skill，中文内容与实现由本项目独立编写。

每个角色目录包含：

- `meta.json`：稳定模板 ID、类型、版本、名称、简介、起聊提示和能力边界。
- `persona.md`：身份与协作、表达与判断、具体对话示例、纠正与边界。
- `work.md`：职责、工作方法、交付与实际能力限制。
- `SKILL.md`：加载入口，引用上述正文及共同交流规则。

[manifest.json](manifest.json) 注册全部默认角色和三类默认档案；[_shared/colleague.md](_shared/colleague.md) 是实际进入所有本地模型入口的共同规则。每个角色的正文构建后生成浏览器和 API 共用的 `research-skills/role-catalog`，原文件随包保留。构建拒绝遗漏注册、缺少正文、断开引用和超出默认聊天输入预算的模板。

## 新增默认角色

1. 复制 [通用同伴](general-specialist/SKILL.md) 所在目录到新的英文 ID 目录。
2. 修改 `meta.json` 的 ID、名称和用途，填写自己的 `persona.md` 与 `work.md`，同步 `SKILL.md` 的 `name`。
3. 在 `manifest.json` 注册 ID。专门助手会自动进入添加列表，无需另写 TypeScript 人设。
4. 加入公开、合成的对话情境；运行根 `pnpm run ci`。客户端调用或设置有变时执行相应客户端检查。

正文写具体的场景、判断和接话示例，不用一串性格形容词代替行为设计。控制默认模板长度，给当前问题、材料和答案留下预算。个人助理模板最多500 UTF-8字节，其他模板最多1600字节，按四项档案 JSON 计；这不是扩大用户输入限制。复杂专业方法放在独立 Skill，按本次授权选择。

## 用户自己创建的角色

不在服务器上为每个用户生成共享文件。名称与简介沿原字段保存，`personality` 对应 `persona.md`，`capabilityDescription` 对应 `work.md`，继续存本人现有的角色数据库记录；自建、导入和聊天创建都使用相同的角色解释与导出器。角色包包含三个 Markdown 文件、明确的元信息和文件清单，可以从「助手设置」查看、编辑与导出；旧版四字段 JSON 仍能导入。

`legacy-profiles.json` 是27份历史默认档案的精确匹配迁移记录，不能用来新增人设。只有全部字段仍与历史模板一致时，查看和模型输入采用新版正文；存储记录不重写。用户改过任一字段就保留其完整档案，空字段采用对应类型默认值。私人交流纠正继续用既有私人记忆、版本和撤回接口，不从抱怨或引用中自动学习，也不进入角色包。

角色不是权限。任务数量、创建确认、资料范围、工具、模型及费用仍由现有服务控制。外部服务的真实人设由远端维护，本站角色档案不会自动传到远端。公开证据执行使用固定审阅角色和严格证据协议，不等于自然聊天替代结构化验收。
