## 当前方向：以个人为中心的 Personal Agent（2026-10-06）

用户明确最终产品：微信式交流、人与Agent统一联系人、按任务类型 / 难度自动组织、长期行为 / 偏好记忆、持续迭代与主动跟进。完整依据为[产品规划v0.7](product-plan.md)。科研小组仍是第一验证场景，个人注册和使用不依赖加入实验室。

当前客户端、API / worker均已上线2e69688，contract0.19 / chat1.8 / schema18，连续文字聊天的真实模型增量、运行中补充、OpenIM投递与刷新去重通过；长文预算限制保留。此前0.18第一批的本人偏好 / 候选确认、专项Agent子请求、同空间协作建议、一次性后台提醒与管理界面继续保留；该批任务路由 / 协作模型检查为本地合成，不以本次聊天验收代替真实复杂任务质量。实际发布版本及证据见[统一状态](current-state.md)。以下目标按纵向流程逐批实现。

| 顺序 | 工作 | 真实使用验收 |
| --- | --- | --- |
| PA1 | 个人助理与最小长期记忆：在聊天中记住明确偏好；获准范围内提取候选、检索、纠正 / 移除；围绕稳定用户身份共用相关记忆 | 换会话 / 刷新后偏好仍有实际影响；明确纠正下一轮生效；其他成员不能读取；避免每条消息都弹确认 |
| PA2 | 按类型 / 难度组织：直接处理、复用专属Agent、必要时创建、再组织人机任务群；接入实际可调用能力 | 简单问题直接解决；专项任务复用同身份；复杂任务真实分工 / 承接 / 交付；不足明确；重复请求不重复建群或派发 |
| PA3 | 服务端持久跟进：截止 / 等待 / 条件变化事件、恢复、去重、安静时段和暂停；回到原聊天 | 关闭网页 / 重启仍跟进；同一事件只通知一次；无变化保持安静；取消 / 完成停止，允许用户调整 |
| PA4 | 反馈闭环：交付评价、经验提取、匹配 / 工作策略与能力版本改善 | 下一项相似任务确实复用相关经验；错误修正有效；版本 / 来源可追溯，改善以结果验证 |

每批先选一个可用的纵向闭环，再扩大自动化范围。例如用户表达“我希望先看结论”，随后提出专项任务：助理应用相关偏好、选择已有Agent或建立角色、记录交付 / 跟进点，用户给出反馈后影响下一次工作。涉及真人时需实际接受；真实外部服务、工具、通知送达分别留证，不用合成模型报告代替。

用户2026-10-06最新优先级是[连续Agent私聊](development/continuous-chat.md)：连发补充、自然短句、真实渐进回复与运行中调整，先完成此聊天体验。后续再补齐个人注册后跨工作空间好友进入任务群的共享 / 接受 / 材料范围；现有同空间任务权限不能静默放开。继续验证真实模型匹配质量、长周期使用中偏好影响与反馈复用，再扩展行为候选、条件触发和周期跟进。当前有限文字路由及一次性提醒不计PA1—PA4全部完成。

现有网页先验证这些后台能力，桌面复用OpenIM Electron工程；原生桌面SDK / 文件 / 通知 / 恢复 / 更新和手机后台 / 推送仍独立验收。优先级以Personal Agent主线及真实使用阻塞项决定，具体工程范围和契约在每批开始时冻结。

## M3：相似课题组及更广泛团队

先验证另一课题组能否采用同一核心产品，再判断是否适用于其他知识工作团队。公共能力复用与个人方法独立并存；跨组织共享需明确授权，不能把组内用户数当作外部平台网络效应。
