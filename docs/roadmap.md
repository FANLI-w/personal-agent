## 当前方向：老师与实验室团队的科研工作平台（2026-10-10）

软件名称确定为 **AcceptCat**。用户明确预期服务学校老师和实验室团队，近期聚焦科研提效、流程标准化与负责人管理对齐，约半年先供本人和学生持续使用。个人助理承担成员工作入口；项目、任务、交付和审阅承担团队共同对齐。个人使用不依赖加入实验室。完整依据与科研R1—R4优先级见[产品规划v0.9](product-plan.md)。

当前优先顺序：基础聊天 / 资料 / 上下文可靠 → 项目目标 / 计划 / 分工 / 交付 / 审阅 / 下一步衔接 → 科研模板复用与真实负责人总览。每批围绕一个实际阻塞和可审阅的结果推进，使用既有任务、材料、权限与版本服务。科研团队核心流程未持续验证前，微信 / 企微连接器、消费级增长、泛行业能力市场及手机端扩展暂缓；原企微试验保留失败事实，安全验证后的回发测试不再是当前下一步。

当前公开版本为Windows0.6.0，配套API / worker11cd20a（contract0.22 / chat1.11 / schema21）；新增私人Skill安装、版本、绑定与文字流程调用。2026-10-09本地0.7.0候选增加[科研任务规划](development/research-task-planning.md)：目标、可编辑步骤、交付物 / 验收条件、分工与依赖，保存 / 重开草案，确认创建实际任务，验收后推进下一步。规划、任务与实际模型来源已按范围分别验证，不代表远端更新已发布或真实小组试用通过。完整自动匹配质量、任意私人Agent / 跨空间分步协作、科研工具执行、长期行为学习与策略改善仍需继续。实际版本与能力边界以[统一状态](current-state.md)为准。

本地0.9.0已实现[科研团队工作台](development/research-team-workbench.md)：获准任务总览、计划步骤与任务持久关联、真实邀请 / 接受 / 阻碍 / 交付 / 修改 / 验收，私人规划绑定发起人的默认模型。603项共享检查与9组合成师生界面流程通过，安装包和云升级记录以当前状态为准。

下一步围绕一个本人正在做的课题，将现有聊天、文件、任务与成果关联起来：导师交代目标，学生与Agent承接，提交阶段材料，导师反馈后继续推进。先核验学生能独立使用、资料范围正确、成果可检查；再扩展数据分析、绘图和文献工具。合成账号流程通过不能代替教师 / 学生的真实任务持续使用。

下列 PA1—PA4 保留为个人助理的工程能力路线，按上述科研团队优先级取舍；不要求先完成完整个人画像和泛行业自主组织才开展课题组试用。

| 顺序 | 工作 | 真实使用验收 |
| --- | --- | --- |
| PA1 | 个人助理与最小长期记忆：在聊天中记住明确偏好；获准范围内提取候选、检索、纠正 / 移除；围绕稳定用户身份共用相关记忆 | 换会话 / 刷新后偏好仍有实际影响；明确纠正下一轮生效；其他成员不能读取；避免每条消息都弹确认 |
| PA2 | 按类型 / 难度组织：直接处理、复用专属Agent、必要时创建、再组织人机任务群；接入实际可调用能力 | 简单问题直接解决；专项任务复用同身份；复杂任务真实分工 / 承接 / 交付；不足明确；重复请求不重复建群或派发 |
| PA3 | 服务端持久跟进：截止 / 等待 / 条件变化事件、恢复、去重、安静时段和暂停；回到原聊天 | 关闭网页 / 重启仍跟进；同一事件只通知一次；无变化保持安静；取消 / 完成停止，允许用户调整 |
| PA4 | 反馈闭环：交付评价、经验提取、匹配 / 工作策略与能力版本改善 | 下一项相似任务确实复用相关经验；错误修正有效；版本 / 来源可追溯，改善以结果验证 |

每批先选一个可用的纵向闭环，再扩大自动化范围。例如用户表达“我希望先看结论”，随后提出专项任务：助理应用相关偏好、选择已有Agent或建立角色、记录交付 / 跟进点，用户给出反馈后影响下一次工作。涉及真人时需实际接受；真实外部服务、工具、通知送达分别留证，不用合成模型报告代替。

连续聊天与完整文字文档阅读保持科研日常基础优先级，参考[连续Agent私聊](development/continuous-chat.md)及[文档阅读](development/document-reading.md)的实际验证。围绕导师和学生的真实课题继续完善跨空间协作的接受与材料范围、成果反馈和项目背景，现有权限不能静默放开。再验证自动匹配、长期偏好与反馈复用、条件跟进。现有有限文字路由、记忆维护和定时安排不计PA1—PA4全部完成。

近期以Windows桌面为主，沿用OpenIM Electron工程。网页与手机扩展后置；原生SDK、文件、通知、恢复与更新按具体改动核验。每批围绕真实科研阻塞确定范围和契约，已有通过的检查不无故重复。

## M2：小组持续使用与 P1 验收

在具备必要运行条件后，用真实任务验证至少一位非开发成员独立承接、可检查交付、人工验收和下一次自然复用。观察整理、催问、操作、检查、返工、交接、模型与维护总投入；记录失败和放弃。提前进行的 G1 人类协作试用单独标注，不代替完整 G5。

优先修复妨碍日常使用的问题，不以增加页面或能力数量替代。开发者全程代操作、返工抵消收益、未发生重复需求时，相关产品结论保留未验证。具体记录见[试点计划](validation-plan.md)。正式账号和备份恢复已独立验证；按[试用启动说明](pilot-launch.md)配置实际主机与访问，再开展 G5b，本次没有部署。

## M3：相似课题组及更广泛团队

先验证另一课题组能否采用同一核心产品，再判断是否适用于其他知识工作团队。公共能力复用与个人方法独立并存；跨组织共享需明确授权，不能把组内用户数当作外部平台网络效应。

个人付费、课题组付费、学校采购、标准产品加实施或有限定制分别验证。优先复用同一核心与可配置模板，记录客户专属开发和维护成本。公开能力市场、支付分成、完整科研行政/经费/人事系统和跨组织自主派发暂不纳入 P1。

每个批次保留明确停止点与证据，按反馈继续、收窄或替换场景；暂不承诺开发周数。当前直接交接[G5b 启动指令](development/prompts.md#当前下一步-g5b)。
