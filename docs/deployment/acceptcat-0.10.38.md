# Windows 0.10.38：规划先交流，减少一次性追问（本机候选）

2026-10-24，北京时间。用户反馈：仅介绍已有研究想继续完善，任务规划就一次抛出多个带长选项的补充问题，缺少交流感并增加用户负担。本批修改生成规则、任务拆解Skill、回复呈现与开场文案，交付本机候选，不自动合并、公开Release或部署后台。

## 实现与兼容边界

从fetch后的main **fecb98f026a85d23a10487c4ff576cb42c8cb76d**新建`fix/planner-conversation`。产品 **22c60b3e1245e11c111b34177b3bd4081a17686e**，含bd01010的核心修改和958b716的旧空标题兜底；[PR96](https://github.com/luoyan96/personal-agent/pull/96)已提交并挂接。

- 生成时先承接已有事实、给有根据的小判断或切入口。确需澄清时，每轮最多一个简单易答的问题；禁止把阶段、方向、优先级、去向和日期塞成复合问题。已有信息不重复问，缺日期/人员等可保留未知，方向清楚或用户要方案时再展开任务。
- canonical任务拆解Skill增加交流前置规则，原拆解/产出/依赖方法保留。现有接口没有独立聊天正文字段，本次沿用Plan结构：目标记录共同目标，零步骤草案可继续交流，至多一个自然澄清项承载当轮回复。没有新字段、调用或后台升级要求；旧0.30接口仍接受相同JSON结构。
- UI不再自动把goal和整个问题数组拼成问卷，直接显示当前交流项。兼容旧计划时只选择首个有效项/首个结构性列表项，不改写原计划或删除其他待定信息；科学引文、代码和URL不按问号截断。其他待定信息仍可随原方案查看，历史消息不重写，可以继续原会话。
- 开场、示例、进度和占位改为从当前研究交流。方案与依赖图、分工和已建任务保持；明确确认、版本/幂等核对、日期核对及取消边界不变。不把自然交流当成自动创建授权。

这同时改变了生成条件与显示方式。结构选择只提供旧格式兼容，不能判断每个模型的语义；约120字/至多一个简单问题是生成指引，不声称前端能证明任意模型一定遵守。
