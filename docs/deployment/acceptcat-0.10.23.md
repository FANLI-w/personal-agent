# Windows0.10.23：资料 Agent 改为底部聊天框

2026-10-20，北京时间。用户明确要求沿用任务规划Agent的底部聊天方式。从实际干净 `feat/library-agent-0.10.22` / `5f1becc` 新建 `fix/library-agent-dock-0.10.23`；未切main或覆盖修改。产品源码固定 **316768dc5707c4c43677f046165d590da194f9b1**。

## 体验与实现

移除资料页中部的Agent跳转卡片和创建弹窗，改为页面底部常驻输入框。直接提问后原地展开对话，支持连续追问、真实流式进度、停止回复、收起/展开、历史恢复和来源核对，不跳转“消息”页。上方继续查看资料集合与文件；资料范围收在聊天框右上角，选择在明确发送时保存。复用0.10.22本人资料Agent和既有私聊，首次发送才创建Agent。

沿用现有 `agentChatMessage`、聊天历史/进度/取消、集合绑定、来源回执和原文片段接口，不新增API、契约、数据库、密钥或模型权限。每人使用自己的Agent/模型；私人/课题组共享范围保持。未选集合时明确只使用聊天内容；资料、代码、PPT和飞书副本的原有能力边界保持。

发送前保存不可变消息、集合选择和请求Key，按当前服务/账号/课题组隔离本机待确认记录；确认保存后再继续。创建/绑定与会话确认逐步记账。未知发送结果只能核对原消息，同Key重试不重复写消息，重启后不更改已派发消息的资料绑定。尚未进入会话发送阶段可返回修改；已派发的未知结果不能直接丢弃后重发。账号/页面/选中会话变化取消迟到响应；读取当前取消版本，不用旧状态覆盖。只展示服务返回的消息和进度，临时生成内容有明确标注。

界面读取最近80个消息序号范围，更多记录仍在既有私聊；服务端仍按实际预算选择上下文，不声称整库阅读。来源/请求详情按需读取，避免对所有历史消息持续轮询。草稿未发送前仅在当前组件内保留，待确认消息持久化；这不是新增多线程会话系统。
