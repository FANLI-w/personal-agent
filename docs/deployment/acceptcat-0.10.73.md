## 审核补修

- 139 原实现删除 blocked 却没有迁移当前存量任务，也会让新客户端拒绝旧后台/历史快照。新增 schema031：仅把当前 blocked 恢复到其原状态，增加版本与系统事件，保留旧任务版本、事件及迁移校验和。共享契约保留旧状态/动作的读取兼容，新流程不再生成 blocked。
- 原撤销实现按任意历史 withdrawn 记录找负责人，非发起人转交后又失去操作权限。新增 `task_handoffs`，明确关联本次邀请、原承接记录、状态、时间和范围。等待接受时原负责人保留读取、撤销权限，单凭该身份不能提交或上传；其既有发起人/审阅人权限保持。撤销只恢复本次原负责人，不能绕过离组、禁用账号或显式撤权。
- 接受/拒绝后收回原负责人的临时读取权限；撤销受邀者权限会关闭对应转交，避免残留 pending 记录阻塞下一次有效转交。邀请已有完整读取权限的人不会降级其权限。已完成成果和事件保留，重放不会重复创建通知或承接。
- 新后台按 `X-AcceptCat-Task-Workflow: handoff-v1` 区分读取能力。旧桌面客户端收到旧 overview/workspace 字段，隐藏未知动作，并把撤销邀请事件投影为旧版可读的撤回事件，保留精确摘要；新客户端仍读精确事件。账号、任务 ACL 和写入校验不因该 header 改变。
