# Windows 任务材料下载恢复

2026-10-16，`acceptcat`；`fix/task-artifact-download` 接续 PR47 / f29917d。使用者是交接科研材料的老师与已接受任务的学生，目标是从任务详情下载当前获准原件，失败后能继续处理。

## 真实问题与修改

`ResearchTaskPanel` 原来将 `/api/v1/artifacts/{id}/content` 作为 `target=_blank` 网页链接。Electron 窗口的 `setWindowOpenHandler` 会把 HTTP 地址交给外部浏览器；桌面代理使用 Electron 自己的 HttpOnly Cookie，外部浏览器没有此会话，不能靠打开链接获得材料。另外，已有通用 `researchApi` 无论路由都读 JSON，直接用它读取契约规定的二进制也会失败。

现在下载在当前应用会话中调用既有 `content` GET 路由。`researchApi` 只为成功的此路由读取原始二进制；其他路由与错误响应继续原有 JSON/会话失效处理。只接受服务已有的 TXT/PDF/PNG 类型，响应声明及实际流读取均受 10 MiB 限额限制，空响应和 HTML 登录/代理页面不能被当作原件。连接和正文共用已有30秒截止，可主动停止并取消 reader，不无限等待。

`TaskArtifactDownload` 取代普通链接。字节大小和 SHA256 必须与当前不可变材料版本一致才生成 Blob 下载，保留中文文件名并清理路径/控制字符。读取失败显示可重试原因；“停止下载”及账号、路由、会话、任务/材料身份或权限状态变化阻止晚结果保存。已撤回元数据禁用按钮，每次真实 GET 仍由服务器重新核验授权。只显示“已请求保存”，不冒充系统保存成功；用户取消系统保存后可再次下载。

不改变科研材料服务、权限、资料库、附件原件、共享契约、内置Skill、数据库或依赖。不新增执行工具、模型调用或外部消息。无法撤销用户此前已经保存到磁盘的副本；正在读取时尚未收到的服务器权限变化仍以该GET授权时点为准，不宣称事后远程删除。
