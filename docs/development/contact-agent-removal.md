# 联系人和自建Agent删除

负责人反馈没有清楚的删除入口后要求补齐。真人及别人拥有的Agent使用既有关系撤销，自建专门Agent增加本人明确删除操作；系统个人助理仍承担默认入口，不提供删除。入口在通讯录名片、详细资料和聊天右键菜单，删除聊天保持独立含义。

## 行为和权限

- 删除联系人只从“我的联系人”移除并停止私聊，不注销对方账户、不取消任务，也不改变群成员或课题组身份；仍可在团队目录发现并重新申请添加。
- 删除本人自建Agent，从联系人/模板复用列表退出、释放活跃Agent额度；历史聊天保留并标记已删除，只读，不再允许新消息或调用。本人可重新创建新身份，不会复活旧Agent。
- 本人确认时的档案版本必须一致；他人不能删除，真人和系统个人助理不能走Agent删除接口。缓存重放仍核对所有者，重复确认不重复取消或清理。
- 停止该Agent待处理/进行中的回复和绑定规划，提升执行fence，阻止迟到正文/提议落盘，同时保留已实际返回的用量。取消其定时工作，停止尚未发送的周期运行和通知消息，清除外部连接密钥；已发送的消息不会撤回。只解除本人私人Skill对此Agent的绑定并递增设置版本，保留其他Agent绑定、Skill正文、修订与来源，避免以后编辑Skill被旧绑定阻塞。
- 不删除原联系人ID、历史消息、任务、资料、成果或私人Skill版本，既有个人角色/记忆记录保留作历史，不做数据清除承诺。角色文字和模型输出不授予删除权限。
- 删除后的群内调用、规划绑定、资料和Skill调用、档案编辑、外部连接及定时工作均重新拒绝；旧默认模板/导入/助手推荐不会把已删除身份作为可用助手。

## 实现与兼容

新增 `POST /api/v1/chat/agents/{id}/delete`，`expectedVersion`是确认的档案版本，返回稳定`id/deletedAt`回执。contract **0.33.0**。既有Contact/Conversation和持久消息结构、allowedActions枚举保持；已删除投影使用既有disabled/capability_unavailable及空动作，旧客户端不接收陌生枚举。

schema **027**新增`deleted_personal_agents`表，保留FK，不改已有表和迁移checksum、不批量删除旧数据。API/worker和迁移单独部署；本批经负责人另行授权已于2026-10-26 12:01:26上线contract0.33/schema027，详见[部署回执](../deployment/contact-agent-removal-20261026.md)。旧0.32镜像严格要求026，不能直接使用027数据库；即使删除表为空也应保留027约束前滚修复，不删除迁移状态来绕过检查或复活旧Agent。禁止回灌旧数据库覆盖后续消息或任务。

前端三处共用同一确认与调用逻辑，按档案/关系分别使用正确版本，保留同一确认的幂等key。页面/账号改变前阻止发送，响应迟到不刷新另一账号；服务拒绝时不乐观隐藏，删除确认后列表刷新失败与删除失败分别提示。通讯录原文数据与聊天发送状态沿用现有读取和权限，删除后重新加载会话只读状态。

## 检查范围

实际本机HTTP/SQLite合成检查覆盖：已有026数据库重复迁移保全、本人/他人/真人/个人助理权限、旧版本和幂等重放、列表/导入复用/活跃额度、历史消息与私人记忆/外部密钥/定时任务、绑定规划及既有真实任务保全、进行中回复迟到与用量保留、私人Skill解绑后仍可编辑且内容修订保持、周期提醒未发阻止/已发记录及另一Agent定时工作保持、真人关系删除/重新添加。客户端检查确认目标/版本/路由、跨账号迟到、服务拒绝和列表刷新失败边界。

完整根CI、双类型、Windows构建和成品核对结果写入current-state/project-log与对应安装包交付记录；失败证据保留。未代用户执行真实联系人或Agent删除，也不追加原生安装、真实账号/私人材料、真实模型或界面体验验收。首次新用例因迁移漏登记失败，补登记后通过；绑定规划用例初稿误设fence初始值，改为核对原值加一，并加入已确认的实际任务保全，不跳过检查或提高时限。
