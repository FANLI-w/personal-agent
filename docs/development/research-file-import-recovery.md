## 实际问题和复现

底层 `researchApi` 原本会为相同请求内容保留幂等编号，所以未经修改的原请求重试已有保护。普通资料导入窗口的问题是未知结果后恢复了编辑：

1. 在本人私人集合导入合成 TXT，实际 API/SQLite 已保存来源；仅测试 HTTP 回执改为 503。
2. UI 显示重试，文件和元数据仍可编辑；修改标题再提交，请求内容变化，因此生成新的编号。
3. 后台因集合版本已增加拒绝第一次新请求；旧 UI 自动读取新版本号。
4. 再次重试会创建第二份来源，而不是确认原来源。

基线 **a2c1061** 用真实 React / HTTP / SQLite 复现两份不同 ID、两个标题的来源，见 Git 外 `baseline-proof.json`；并不是后台完全没有幂等去重。本批没有改变既有去重协议或提高权限。

另一个实际链路缺口：`useResearchRead.refresh` 有意捕获并展示读取失败，其 Promise 不抛错。只在导入组件中捕获 `onSaved` 失败不足以判断实际列表刷新失败。最终用真实 HTTP 读取 503 验证并补齐该传递。

## 修复入口与规则

工作台 → 资料与素材库 → 选择本人获准集合 → 导入文件；已有来源详情 → 导入新版本。沿用猫咪主题。独立 `ResearchFileImport.tsx` 使修改局限在导入流程，旧 `ResearchLibrary.tsx` 的集合编辑、来源下载、检索和 Zotero 入口保持。

- 首次发送建立内存快照：文件内容、媒体类型、元数据、集合/来源版本及独立 UUID。同步 `busyRef` 阻止短时间重复提交。
- 网络、超时、5xx、无法读取响应等未知结果：暂锁文件/元数据编辑，显示“导入结果尚未确认”，重试使用相同完整正文和编号；不因集合已更新而重写未知请求。
- 明确校验、版本、权限等未写入拒绝：解除编辑锁并保留输入。同范围的版本冲突读取版本后，由用户再次点击提交。**范围类型或任务授权集合变化、集合不可用/不再属于本人时，阻断继续上传**，不静默升级到公共/团队资料。只核对当前最多100个本人集合，超出未找到时保守拒绝，需重新选择。
- 成功收到真实服务器结果后记录来源/当前版本。保存和列表刷新分离；刷新失败显示已保存，按钮只重读列表，不调用 importResearchFile。后台幂等回放返回当前来源状态，版本文字表示收到的当前状态，不伪称模型读完或科学结论验证。
- 共用 `useResearchRead` 增加可选 `refreshChecked`，捕获调用对应的读操作/范围/世代并传播其失败。原 `refresh` 的非抛错轮询、合并在途读取、超时、退避和账号隔离行为保持。仅普通文件导入回调使用 checked，其他调用方无需改类型。
- 账号/页面身份变化关闭旧窗口、丢弃晚回执；不把 A 的提交状态写入 B 页面。
- 居中窗口、内部正文滚动，1024×726仍能到达错误/操作，标题/关闭入口固定可见。未知结果主动关闭时提醒可能已保存，取消关闭可继续确认；没有跨重启的请求持久恢复。
