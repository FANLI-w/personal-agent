上部“研究方向与任务”按现有计划关系归组，区分准备开展、正在推进、已结束；点击方向定位下部。下部“目标与任务进度”列每组验收进度、任务、已承接负责人、未接受邀请、待认领、审阅人、截止、阻碍、成果和下一步；可筛选、搜索、快速查看、打开准确任务并回到所属计划。成员分工显示实际已承接/待审阅与另待接受的邀请。

## 数据与权限

复用 contract 0.23+ 的 researchWorkspace 接口，无新后台或迁移。客户端以 limit100、同一 snapshot 连续读页，最多10页；跨页失败、重复 ID/cursor、版本变化不展示部分完整进度，取消信号贯穿读取。超上限明确显示读取数量/全范围总量，下方仅统计已读取任务。全范围统计沿原服务端 summary，不用当前页推算。界面按8组分页，搜索/状态覆盖本次已读取集合。

只按真实 planId 归组；摘要投影没有 planId，不能根据标题/人名推断其私人计划。本人可看到服务器返回的本人目标，其他成员以获准任务名称概括任务组；私人草案仍属于本人，不因展示透明进度而公开。任务按可见依赖排序，不以标题匹配任务。准备开展包含未承接/待开始，真正执行、阻碍或交付进入推进状态。

进度分子要求 task completed 且当前 latestDeliverable.review.decision=accepted；已取消项排除分母。发出邀请、模型运行成功或提交成果不算验收。科研目标达成与研究质量仍需导师判断。个人空间不读取或显示课题组任务内容，只有加入说明与我的任务入口。既有成员和任务 ACL 保持，未为本次 UI 新开权限。

这不是独立共享研究方向或完整 OKR 管理后端：共享方向命名/编辑、多个计划归属同一长期方向、专门关键结果指标和全组公开目标审批仍待后续设计。当前提供用户要求的目标/任务层级进度，并明确保留已有隐私边界。
