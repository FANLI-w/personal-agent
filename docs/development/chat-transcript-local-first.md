# 完整聊天记录本地优先（2026-11-04）

## 问题与本批范围

负责人已明确要求按本地聊天记录读取，实际实现却只缓存了 OpenIM 的 MessageItem。科研自定义消息只有 `research_message` 指针，ResearchMessageRender 仍逐条向 API 索取正文；useResearchRead 默认每五秒刷新；上翻历史仍直接走 SDK。因此“本地消息列表已出现”不代表正文和历史分页已本地化。把前一批称为完整的微信式本地记录是不准确的。

本批在独立分支 `fix/chat-history-complete-local` 修复读取链路。没有清空任何账号、后台记录、附件或已有本机聊天数据库，没有操作负责人的真实客户端。清库不会修复上述客户端路径。

## 数据路径

- 同一服务、同一账号的既有 SQLite 文件新增本地 `research_records` 表，原 messages/edges/meta/overlay 保留。完整正文、引用关系、最后获准的 Agent 回执和群内公共状态随快照落盘，重启后可以恢复。完整同步快照一次写入一条记录，辅助索引可从该记录重建。
- 打开会话和继续翻页均先读本地；只有缺失页才取 SDK。已缓存的科研正文不再等待 API，也不再逐条定时索取。未下载过的正文仍需首次联网补取，旧版只缓存的指针不会凭空变成正文。
- 最新页联网核对独立于本地展示。缓存检查结束前不启动空列表重试；本地命中后，核对失败不再留下“历史读取失败”提示。账号或会话切换的当次渲染立即隐藏前一范围的消息，不等 effect 清理。
- 新接口 `GET /api/v1/chat/conversations/{id}/transcript-sync` 接受已知 messageId/revision，每批最多40条；客户端每批20条。服务端只返回发生变化的快照和不可读 ID。没有变化时不返回正文。
- 当前会话中已挂载的消息共享同步器。活跃请求五秒核对，其他状态三十秒；后台页面/明确离线不发同步请求，回前台或联网后重新核对。客户端不再为每个历史气泡各开一个正文轮询；旧后台仅对未结束的 Agent 请求保留原状态读取。
- 本机已获准下载的历史记录可直接阅读；在线发现消息或会话不可读时清理相应快照。实时业务动作仍由服务端验权。转发明确重新读取源消息，撤回重新核对版本，缓存不能赋予任务、资料或模型调用权限。
- 撤回快照不能被迟到的原文覆盖；租约 IPC 按接收顺序执行，避免异步 cookie 核对打乱写入次序。删除消息同步写入本机删除事实，删除会话清理对应 SDK 和业务缓存，不删除服务器科研对象。
- 本地保存失败明确显示缓存故障提示，不能悄悄退回联网读取后仍声称已持久保存。内存缓存与 SQLite 分开，账号 generation、主进程 cookie/服务身份和每账号文件共同隔离；晚到响应不写进新账号。
- 新出现的消息唤醒批同步；本机已经确认的重试/取消会更新记录代次，旧批响应不能将其覆盖。正在同步时收到唤醒请求会在结束后补一次，不丢失刷新。

## 后台与兼容
