# 课题组能力身份与聊天列表入口

2026-10-18（北京时间），`fix/lab-capabilities-entry` 接续 `release/acceptcat-0.10.13` / `ff0f21e`。本批只修改客户端，尚未制作新 Windows 安装包、部署后台或公开发布。

## 用户可见调整

- 移除聊天标题旁的收起列表按钮、聊天区的重新展开按钮及其专用 Zustand 状态和样式；桌面保留聊天列表、搜索与新建菜单。原有窄屏按路由切换列表/会话的行为保持。
- “我的 → 课题组能力”先检查服务端 session 的 `spaceKind`。个人空间显示未加入的空状态，不挂载能力浏览器、不读取课题组目录，也没有搜索、分类或公开操作；个人 Agent 仍在“我的 Agent”。
- 身份尚未确认时显示检查状态，读取失败显示错误及实际重新读取入口，不把未知身份写成“未加入”。已确认课题组账号仍沿用同组目录与原权限。
- 课题组页复用既有账号说明；只有服务器确认的负责人显示实际服务地址下的网页邀请管理入口。账号/课题组变化重挂载浏览器，旧目录请求在切换个人身份时取消，迟到结果不重新显示。

此前界面没有区分个人空间与 laboratory，直接读取当前空间目录，导致个人账号自己的资料与 Agent 也出现在“课题组能力”。此次修正显示和读取入口，不修改资料授权或服务器目录接口。

## 课题组目前怎样管理

实际实现来自 `apps/api/src/maintenance.ts`、`registration.ts`、共享 `session` / `managerInvites` 契约，以及客户端 `ResearchTeamAccountHint`：

1. 后台维护者通过既有维护工具创建课题组、指定负责人开通邀请码或已有同组负责人；客户端没有自助创建课题组入口。
2. 负责人登录实际服务的 `/manage/invites` 网页，签发或撤销有期限、次数限制的成员注册邀请码。
3. 成员使用有效邀请码注册，对应账号加入该课题组。不填邀请码则创建独立个人空间。
4. 添加好友和发起群聊不改变课题组成员身份；当前没有现有个人账号直接加入、课题组切换、多课题组或完整成员移除/转移的客户端流程。

后台已有维护级账号停用和负责人指定，不代表负责人已有完整的成员管理界面。后续可围绕“教师创建课题组 → 邀请已有账号 → 本人接受 → 管理成员与共享范围”补齐自助流程；群聊可关联具体课题或项目，其成员与权限需要分别明确。本批没有新增这些接口或改变现有账号归属。
