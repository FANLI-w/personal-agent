# 工作台任务规划 Agent

2026-10-19，Windows 0.10.18，接续 release/acceptcat-0.10.17 / b11e1f5。用户要求像普通 AI 聊天一样安排任务，并把原来的右上“规划新任务”入口改为底部对话。产品源码固定 **8bf46f17ee720f2e8c5e028001b4dda384c077db**。

## 使用方式

工作台课题组任务与我的任务底部常驻输入框。说出目标后展开对话，Agent 可以追问、生成任务方案，继续用自然语言修改目标、分工、依赖与交付要求。输入“确认创建任务”或点击同一对话内的创建动作后，才把当前审阅过的版本建立为正式任务。邀请仍等待成员本人接受，创建回执给出实际任务链接，并刷新课题组进展。可展开为我的任务 → 研究计划中的完整聊天；计划记录折叠，旧 plan/planning 链接接入对应上下文，不再打开原多步编辑器。

这批沿用原桌面品牌、字体、浅蓝、三个主栏目和 0.10.17 的方向/任务进度。资料库与定时安排、联系人协作和个人助手的任务详情/返回聊天保持原有路径。

## 数据与执行边界

- 使用现有 planRequest/getPlanRequest/getPlan/editPlan/confirmPlan/planTasks/cancelPlanning。没有新 API、共享包、Skill 内容或数据库迁移；既有 contract0.25 服务兼容，planTasks 最低0.23。
- 每轮使用当前私人草案的真实 ID/版本，最近最多12条连续对话和最多20个实际同组成员，提示总长不超过8000字符；截去的上下文有提示。模型输出仍通过现有结构/成员/权限验证，不能编造任务成功或默认成员接受。
- 对话、未发送输入及待核对写入意图按服务地址/账号/课题组保存在本机。最多20段、每段60条；本机记录不是业务权限依据，不自动跨设备同步。服务端计划/任务仍为真实业务记录。换账号/空间/对话后迟到响应隔离；恢复不会自动重发写操作。
- 发送和确认各自保留首次幂等键。未知回执显式核对原操作；确认前重读版本和完整内容，只识别本操作的精确日期编辑或已确认任务，其他窗口改动必须重新审阅。合成验证中实际确认已提交后返回503，核对后仍只有三项原任务。
- 现有 worker 不把模型猜测的日期直接变为承诺。本批把用户明确说出的完整日期、今天/明天/后天或周几按北京时间显示，默认最终交付，也支持明确的数字/中文序号步骤或全部任务。一次待确认截止安排；复杂多日期、时刻、否定或无法解析的表达要求继续澄清，不能据此直接确认。多项独立截止的完整对话编辑仍需扩展，不能称为通用日程理解。
- 停止先核对同一请求最新状态，排队到运行的409最多再读一次；已完成不再取消，取消仍由后台阻断迟到模型结果。已确认任务通过任务详情调整，本批未提供用新一轮聊天直接改写已确认任务承诺的能力。
- 没有模型配置时保留消息原文并显示模型设置入口。网络未知失败保持原操作待核对；验证/模型不可用等明确拒绝允许修正后重新发送，不自动消耗模型重试。
