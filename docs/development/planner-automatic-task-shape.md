# 任务粒度自动判断

2026-10-26。负责人反馈“合为一项任务”点击无反应，并希望取消模式切换。原按钮只改本机taskShape标记，多项本来就多项时不会重新生成内容；无法安全合并时又受分工/日程校验阻止，不是可靠的对话修改入口。

## 行为

- 删除一项/多项提示行及切换按钮。助手按实际工作判断，用户用对话要求合并、拆分或修改；不是改一个标签冒充任务已修改。
- 默认自动安排：普通目标一项，准备、实验、检查、写作是内部步骤。只有确需独立分工、分别交付/跟踪，或大项目有多个独立成果及真实前置关系时，才建议多项并简短说明理由。难、重要、动作多或论文多本身不构成拆分依据。
- 内部auto只表示采用助手返回的完整草案，不新增API输出字段或要求模型输出single/multiple标签。明确要求一项时仍保留原内容合并校验；明确要求多项时按对话重写。预览和创建使用同一函数与快照，始终要用户核对数量并确认，不自动派活或创建。
- 保留旧草案已展示的数量；每轮新规划默认auto，携带真实对话让助手理解修改，不继承旧按钮或上一轮的数量锁。当前明确的一项/多项表达可约束该轮，其他自然表达由模型结合上下文判断。正在重试的创建快照保持原taskShape、内容与幂等键；已确认任务照实显示。无数量标记的旧多项写入仍需重新核对后才能继续，不绕过旧保护。
