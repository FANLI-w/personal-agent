# 聊天附件先进入输入框

2026-11-09，按负责人两张截图调整聊天输入区。代码从最新main/289eb3a的独立工作副本开发，交付分支fix/chat-composer-staged-attachments。

## 行为

- 移除工具栏第二个扩展功能入口和语音入口；保留表情、附件选择、截图。群聊仍可在输入框键入@选择成员或助手。
- 文件选择、拖入和浏览器暴露为File的粘贴统一暂存；PNG/JPEG等图片按MIME或扩展名识别，MIME缺失时补齐图片类型，不再因使用文件按钮而发成普通文件。
- 图片缩略图和PDF/PPT等文件卡片放在同一个输入框内，可逐个移除、补充文字。选择附件时不上传、不创建SDK消息；点击发送或Enter后才进入原发送队列。附件发送后可继续选择下一批。
- 同批按输入区展示分组先发图片、再发文件，最后发送配文。图片沿原图片发送/OCR链，文件沿原业务读取和权限规则；这次没有给群内Agent扩大附件读取权限。
- 文件保存SDK消息ID、已收到回执及后续处理状态；失败保留原记录，重试复用ID并跳过已完成项，切换会话或账号停止原发送。单文件发送与后续处理有120秒等待边界，超时保留记录核对结果。
- 大文件原件不写入sessionStorage。刷新后恢复的是暂停记录和附件元数据，丢失原件时明确要求重新选择，不偷偷退成仅发文字。普通文件未新增字节大小限制；暂存最多20份文件，图片沿原有20张/10MiB每张/50MiB总量边界。

现有图片OCR、截图与消息播放能力保留，去掉的是录音操作入口；没有全仓删除音频类型、播放器或其他页面功能。

## 同批修复：截图不再隐藏当前聊天窗口

负责人随后提供三张截图，确认当前可见的是AcceptCat，但预览截到了背后的其他应用。主进程chatScreenshotManage原来会hide当前窗口、等待250毫秒、抓屏，再在finally中show/focus；这是主动改变了被截画面，并非附件发送或裁剪坐标错误。原测试也按隐藏/恢复窗口来验收，未覆盖用户要截当前界面的场景。

本批移除hide、250毫秒延迟及show/focus，直接抓取当前可见桌面，截图返回后才打开已有框选预览。成功、失败或超时均不主动改变窗口层级和焦点；原可信窗口/焦点检查、单次抓屏、并发互斥、15秒期限、身份变化丢弃结果与画面大小边界保持。

回归夹具用可见性决定返回前台或背后像素，旧代码6项截图测试中4通过、2失败，修复后6项全部通过；连同5项真实preload/main IPC权限检查共11项通过，Electron typecheck通过。证据在Git外screenshot-visible-before.log、screenshot-visible-after.log，位于D:/deepseek-agent/.runtime。这里使用合成Electron/compositor边界，未对负责人正在使用的桌面抓屏或安装新版，真实Windows抓屏体验仍需新安装包验收。
