# 科研同伴团队：角色、方法与实际能力

2026-10-26。负责人要求整体打磨科研助手，覆盖科研、项目和知识产权场景；由本批维护实现，实际体验仍由负责人检查。

## 分工与交付

保留Persona/Work/Skill文件组织，共18类角色，其中15类专门助手出现在添加列表，个人助理沿原绑定入口，通用同伴与固定证据审阅角色保留各自用途。

| 分工 | 角色 | 主要交付 |
| --- | --- | --- |
| 基础 | 个人助理、研究方案助手、资料助手 | 接住当前需要、推荐适当同伴；一个目标默认一项任务；带来源的资料回答 |
| 论文 | 研究选题、文献阅读、实验设计、实验与复现 | 推荐问题与最小验证；有边界的文献解读；关键对照、复现诊断与分析代码 |
| 论文 | 论文写作、论文润色、论文修改 | 有依据的正文；保留原意的改稿；审稿问题与修订对应 |
| 论文/项目 | 科研绘图 | 数据图、机制/架构、项目路线的可编辑结构、代码、图注 |
| 项目 | 项目申请、科研PPT | 指南对照、论证审阅及允许的辅助稿；逐页内容、布局与讲稿 |
| 知识产权 | 专利交底、软著材料 | 技术方案与支持关系；真实软件文档与材料一致性核对 |
| 协作/审阅 | 组会汇报、科研同伴、证据审阅同伴 | 进展与卡点、可操作的研究判断、有范围的证据核对 |

每个角色写明工作场景、判断取舍、接话示例与限制。默认先利用材料给判断和可用结果，只有下一步被阻塞时问一件关键事；不把方法字段变成首轮问卷，也不强行把讨论转任务。说话风格随职责不同，私人纠正优先沿原授权使用。示例不能变成用户事实或共同经历。

## 角色和方法的接入

meta加入category/teams/methods，构建校验分类、分工、方法目录及SKILL链接。新角色仍按同一模板和manifest注册，不在TypeScript另写人设。个人助理默认档案491 UTF-8字节，其他默认不超过原1600字节上限，共同规则保持；详细流程放独立方法，避免挤占当前问题与答案预算。

原11个方法继续保留，补8个方法：选题、绘图、项目申报、科研PPT、专利交底、软著材料、资料使用、论文润色。实验矩阵补领域判断、实验单位/混杂/重复、随机化与功效考虑；不把所有科研都当机器学习。

19个方法从canonical文件生成浏览器可导入目录，用原解析器校验，文本规范化为LF。软件技能库增加“内置方法”，打开时才加载正文/参考；优先提示适合当前默认角色的方法，改过职责/性格的角色不硬套推荐。选择后进入原预览与确认安装流程，仍为本人私人副本，绑定及每次选择仍需明确操作，不扩大资料或工具权限。既有私人技能与版本不自动更新，普通聊天也不悄悄安装或加载整套方法。

## 工具、证据与规则

当前普通聊天/安装Skill调用仍是文字执行器，没有因本批增加浏览器、脚本、图像生成、PPTX导出或实验设备控制。绘图可给结构/源代码，PPT可给逐页内容或生成代码；只有真实工具调用产生文件且得到回执才能说文件已生成，只有实际查看才能说视觉检查通过。不得把预期实验、未经检索的新颖性、未经导出的文件或未核实的注册/授权状态写成完成。

项目申请按资助方、年份、项目类型和AI规则处理。[国自然申请书说明](https://www.nsfc.gov.cn/p1/2961/2962/3642/sqs.html)及[2026通知](https://www.nsfc.gov.cn/p1/3381/2824/99667.html)要求真实性和人工核实，并限制直接使用生成式AI申请书；这类场景辅助资料与作者论证，不交付可直接提交的整份AI代写稿。其他项目按其实际指南判断。专利与软著按官方当前要求和真实材料准备，不承诺授权/登记、自动递交或改变权属。

## 兼容、检查与交付边界

10份上一版完整默认档案追加到原27份精确历史表，合计37份。仅全部字段仍匹配历史模板时只读投影新版，保留原名字；任何用户改动、联系人ID、私人记忆、已安装技能/修订和已创建任务不重写。新增方法源kind沿copy、source.revision保存方法摘要，不增API字段、数据库表或权限。

代码检查覆盖原文/包内一致性、所有角色实际进入HTTP/SQLite合成模型输入且守预算、方法私人安装/显式绑定选择及他人不能读取、导入导出及旧角色复用。公开对话情境见[评价情境](../../evaluations/fixtures/research-colleague-team.md)。这些检查不证明真实模型交流质量或真实安装体验；实际结果、失败证据、安装包与后台状态另记current-state和project-log。
