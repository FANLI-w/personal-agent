# DSH 第三步：课题组文献协作

日期：2026-10-28。功能分支 `feat/dsh-team-coordination`，基于第二步 `30f696a`。开工核对 main 为 `93da480`；PR130、131、132 是尚待合并的前置变更。本批不合并、不部署、不公开发布。

## 使用方式

1. 群里正常沟通、提及与引用仍用现有聊天流程。对已进入业务记录的群消息右键，选择 **安排文献任务…**。
2. 从已加入群的本人/同事的个人助手中选择最多五位，分别填写任务名称和整理要求，确认分工。系统显示助手名称、归属；不会把群成员资格当作私人记忆访问权。
3. 本人的任务等待开始，同事的任务先邀请本人承接。群标题的 **协作任务** 可看到全部分工及原消息入口；有任务权限的人才能打开详情和成果。
4. 负责人在任务页 **安排与验收** 中接受、开始，再在 **执行** 页使用本机 DSH。在 **资料与成果** 选择获准资料、核对输出并提交；审阅人检查后验收。每个子任务有独立会话、文件和成果。
5. 群内收到关联原消息的状态回执：待承接、执行、结果待核对、本轮结束、待验收、已验收等。通知不触发 Agent 再回复。工具日志、私人路径和私人记忆不写入群回执。

当前支持同一课题组已加入群的本地个人助手，使用公开档案作为角色参考；不通过该入口委托外部 Agent，也不自动获取同事机器文件。群内普通 `@` 问答继续现有链路；安排任务是单独的明确动作。AI 分工建议仍使用已有聊天/计划能力，本批没有新增自治拆解或 Agent 互相派单。

## 执行与恢复

- 服务端以任务 ID 仲裁唯一活跃执行，`claimed / running / uncertain` 均占用执行槽。一个执行请求使用稳定 requestId；结束后的同请求重放不会再调用模型。
- 本机按服务和账号保存随机设备 UUID、执行回执、会话和事件位置。修正原先用目录摘要当设备 ID 的方式，两个电脑相同目录不会自然得到同一个设备 ID。原任务工作文件、会话与历史保留。
- 主进程每 5 秒核对本地终止事件并续报；切换聊天页面不依赖 React 组件继续心跳。只有本轮的新终止事件且本机会话不在运行，才上报结束。排队成功、旧终止事件与暂时空闲都不能冒充本轮结束。
- 心跳超过 30 秒或过了截止时间，后台显示结果待核对，**不会**释放执行槽给另一台电脑。原设备重新打开任务可核对已完成事件；回执丢失时用户重试原请求，复用 DSH requestId。
- 撤权或失联时尝试停止本机会话；无法核实终止时仍保持待核对。原执行者/设备可以在撤权后上报终止，但不能再开始执行。原设备永久丢失时本批没有强制远程解锁按钮，应先由维护者核实本机已停止，不能直接重跑未知副作用。
- 群协作每个子任务最多 3 次明确执行，每轮截止 3 分钟；主进程检测到 12 次模型尝试时请求停止。轮数由后台拒绝超限请求；时间/尝试数是周期检测与取消，不能声称能撤销已经发生的工具效果。模型网关仍沿用既有单请求限额；本批没有独立的任务人民币费用结算或硬扣费上限。
- 设备在线表示最近打开过任务工作端且心跳有效；不承诺用户整个电脑在线。没有后台自动拉取任务、无人值守排队或自动切换设备。直接在独立 DSH 页面运行的自由会话不属于任务协调机制；任务执行应从任务工作页发出。
- 群状态由服务端原始任务与执行事实生成，人工承接、提交、审阅时立即发布；离线状态在读取时核对。成果正文保持既有任务/附件权限，群回执只提供获准的任务链接，不扩大读取权限。
