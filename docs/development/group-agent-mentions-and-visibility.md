# 群聊中的多个助手与状态读取

2026-10-26，修复同事群聊中不能同时叫到两个助手、其他成员看到“AI 请求状态暂时无法读取”，以及新普通群聊请求上下文预算过小的问题。客户端0.10.59与配套API contract0.34需要一起使用；数据库仍schema027，无新增迁移。

## 交互与执行

在消息开头依次输入或从提及菜单选择 `@助手甲 @助手乙 问题`，可以夹带真人，最多同时5个本地助手、20个成员。保留UTF-16精确范围、空格边界、同名/重复校验；转述、引文和正文内部的@不自动派发。外部服务助手仍须私聊并逐条授权。

成员候选来自当前会话的已加入成员公开档案，最多100人，不再依赖自己通讯录里是否缓存了同事的助手。邀请未接受、退群或已撤销成员不能成为调用目标；名单读取失败时不截取目标或悄悄只发送给第一个助手。

发送只持久化一条真人消息，为每个目标建立独立持久请求。批量请求字段agentContactIds与旧agentContactId互斥，必须逐个对应显式提及；旧单助手接口保留。新增可选响应turns注册全部进度，旧单助手响应不增加字段。事务中任一成员/容量检查失败则整批回滚；幂等重放返回原请求的当前状态，不再创建消息或请求。刷新待发记录保留全部目标、原预算与幂等键，暂停等本人处理，不自动发送。

新普通群聊每个助手预留16000tokens/90秒，客户端发送整批总额，服务端向下均分，合计不超过授权总额，最多80000tokens/450秒。高级面板显式预算、历史排队和重试的原总额不自动提高。关联同一工作任务时只捕获一次版本，首位助手保持主要结果的跟踪；其他回答留在群内，不额外创建任务，也不把多位助手都标为完成原任务。

## 权限与状态

共享的群消息不再暴露其他发起人的私有turnId指针。模型正文仍先检查当前群成员和材料权限，不能借此绕开资料撤权。chatTurn、chatTurnProgress及重试/取消权限仍限请求发起人。

新增chatMessageAgentStatuses提供本群消息各请求根的最新公开状态：助手ID/公开名称、状态、失败代码、结果消息ID、更新时间和状态记录ID。没有预算、用量、模型配置、请求原文、私人记忆、文件/资料回执或操作权限。客户端在真人消息下分别显示等待、回复中、已回复或失败原因；发起人仍可使用自己的完整状态。其他成员不再读取发起人的私有进度接口。

群和消息、材料ACL每次重新检查。仅接受助手邀请的主人未加入真人群时仍无群历史权限；退群后不能读名单、正文或状态。私有状态404不被伪装成助手已经回复；超预算继续显示真实失败，历史失败不会因升级自动重试。

## 验证及上线边界

合成HTTP/SQLite回归覆盖双助手独立回复、其他成员读取公开状态、私有请求详情拒绝、重复发送幂等、非法成员整批拒绝、达到并发上限时部分插入回滚、显式低预算、工作任务版本和资料撤权。客户端回归覆盖提及范围/上限、普通预算、跨账号边界和批量待发恢复。真实模型表现、安装和产品操作由负责人检查，自动化通过不代表已经代验真实群聊。
