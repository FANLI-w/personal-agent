# AcceptCat 与本地 DSH：三步改造计划

更新：2026-10-28。用途：后续开发的执行与交接入口。

## 结论：按一个整体设计，分三个可用版本实现

可以一次集中开发，但不建议一次性替换全部界面和执行链。聊天身份、任务状态、资料权限和本机执行同时改动，出问题时难以判断原因，也难以保留旧功能。

因此只分三步：**先能在任务里工作，再能持续记住工作，最后让团队一起工作。** 每步都交付能使用的功能；上一步验收后进入下一步，不另外铺开长期功能清单。

最终形态：AcceptCat 管统一界面、身份、任务、共享资料与协作；DSH 管本机 Agent 执行、工具、文件和插件。聊天是沟通入口，任务是工作载体，资料是有来源的输入与成果。

## 第一步：把 DSH 变成真正能办事的任务工作页

**使用效果：** 从聊天确定一项工作，进入对应任务，在同一页面看目标、问助手、处理资料和交付成果。

实现内容：

1. **统一入口与工作页。** 复用已有聊天确认创建任务的流程；聊天中的任务入口、任务列表打开同一任务。工作页包含目标、负责人、交付要求、DSH 对话及可展开的资料/文件/运行记录。普通问答仍直接回答，不强制建任务。
2. **绑定任务与执行。** 用稳定 ID 关联任务、Agent、DSH 会话、执行记录和设备。不同任务隔离上下文；切换页面或重启后能找到同一任务与历史。技术重试不能隐式重复有副作用的工具操作。
3. **接入实际资料。** 经现有权限接口读取用户选定的资料与版本；本机文件由本人选择工作目录。引用可定位到原资料，缺权限或读取失败如实提示。
4. **成果回到任务。** DSH 生成的文件和结论可预览，并由用户提交为任务成果。沿用既有提交/审阅/验收流程；本机路径不能冒充同事可访问的共享成果，提交共享文件须走授权存储。
5. **保存最低限度进度。** 持久记录运行状态、产物引用、下一步和阻碍。断线显示中断/待核对，不自动宣布成功；这份任务记录为第二步的交接记忆提供依据。

验收：用合成资料完成“从聊天建立一项文献对照任务 → 本机 DSH 读资料 → 生成带来源的对照表 → 提交 → 验收”。切去另一任务再回来不串台；重启能找回进度；未获授权的资料无法读取；重复点击不产生重复交付。

本步先做好一类工作，使用官方扩展接口与适配层接入固定 DSH 版本；不同时重写整个 DSH UI。接口可用性在本步验证，不把未验证的上游能力当作已经存在。按负责人后续决定，原工作台入口在第一步改为“任务”，旧业务放在“安排与验收”及现有计划/群协作入口，保留旧链接和数据。

## 第二步：让规则与记忆真正服务持续工作

**使用效果：** 用户不用每次重复背景；可以查看、纠正和撤回记忆，也能看清本次工作使用了什么规则、资料和 Skill。

实现内容：

1. **规则管理。** 增加平台基本规则、课题组规则、项目约定、个人偏好和本次要求的管理入口，显示制定者、适用范围、版本与生效情况。继承已有规则，不要求用户先填写整套“宪法”才能使用。
2. **任务交接与项目记忆。** 在工作检查点形成“结论、证据、下一步、阻碍”的短摘要，关联任务与原始记录。换 DSH 会话仍能继续；旧摘要保留版本，执行日志和原始资料另存，不反复塞进长期记忆。
3. **记忆的确认与纠正。** 个人记忆复用既有确认/修改/撤回接口。工具实际完成的动作可自动形成进度；模型推断的个人偏好和团队共识先作为候选，由有权的人确认。群聊不默认读取成员私人记忆。
4. **统一索引与按需读取。** 自动维护任务、会话、文件版本、成果和记忆的关联；检索前检查权限。每轮只带简短必要规则及相关上下文，详细规范和 Skill 按需读取；展示规则/工具/资料的使用依据与上下文占用。

验收：第一步的任务完成一半后换会话，新会话能说清已完成内容及下一步，并找到原成果；规则更新能追溯，个人记忆纠正后后续回答采用新值；另一成员不能检索到私人内容；普通问候不会加载整个项目档案或全部 Skill 正文。

4KB 交接、8KB 项目摘要只作为首版参考预算，结合实际 token 和恢复效果调整，不当作所有工作的永久硬限制。索引负责定位，任务状态、资料正文、记忆记录分别保留唯一事实来源。

## 第三步：让两个人和各自的 Agent 协同工作

**使用效果：** 群里明确请求或分配工作，每个人的本机 Agent 处理获准任务，成果回到同一任务和原群，大家能看清谁在做、卡在哪里、谁来验收。

实现内容：

1. **群内请求接到工作页。** `@` 自己或已共享的 Agent，明确身份和归属；引用回答继续追问能关联原请求。共享给群的 Agent 不携带其主人的私人聊天与记忆。
2. **协作与任务状态贯通。** AI 推荐拆解和分工，正式安排沿用人的确认与成员承接。各子任务有独立上下文、负责人和成果；状态区分待承接、执行、阻碍、待验收与完成。
3. **本地设备执行协调。** 首版每次执行只由一台获授权设备领取；离线显示等待上线，断线显示待核对，避免同一任务多设备重复运行。团队任务授权不等于获准操作对方电脑的全部文件。
4. **回执与共享结论。** 接收、进度、失败和成果回执关联原请求；按预先授权的范围回到任务与群聊。明确区分消息送达、成果提交和验收完成。Agent 自动往返设次数、时间和费用预算，通知不自动触发互相回复。
5. **完成入口整合。** 验证旧任务及资料链接仍可访问后，以统一工作页承接原工作台入口；迁移保留历史记录与回退路径，不以删除旧业务数据完成替换。首版只用“文献整理”场景，不铺开场景市场。

验收：两个合成账号、各自一个 Agent，在同群分别处理一组文献；两份成果独立提交并可审阅。覆盖同时请求两个 Agent、引用追问、一台设备离线、其中一个任务失败、权限撤回及重新登录；不能串用私人记忆、重复执行或把未验收成果标成完成。负责人再做真实双机使用验收。

## 三步始终遵循的管理方式

这些边界从第一步起执行；第二步补齐管理界面，不是等第二步才做权限。

| 对象 | 管理与保存方式 |
| --- | --- |
| 平台基本规则 | 产品维护者管理；权限、预算、执行与验收条件由代码检查，科研真实性等行为要求配合提示与证据校验 |
| 课题组/项目规则 | 获授权负责人发布，只作用于对应团队工作；不扩大对成员私人数据的访问权 |
| 个人偏好/本次要求 | 本人维护；临时要求不自动变永久规则，偏好不能绕过权限 |
| Agent 与场景 | Agent 是参与者；场景是可复用的工作流程与界面模板；任务是一项具体交付，会话可以替换 |
| 共享任务与资料 | 现有 AcceptCat 服务是权威记录；本机缓存、索引和记忆摘要不能另建一套相互冲突的事实 |
| 本地执行 | DSH 负责本机工具与文件；共享写回走授权接口，版本冲突提示处理，不能用旧副本覆盖他人改动 |

规则变化由有权的人决定。Agent、资料原文、工具输出只能提出建议，不能自动修改规则或提升权限。个人助理既可以协调，也可以直接完成简单工作，无需每件事都派给另一个 Agent。
