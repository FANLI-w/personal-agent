# 工作台：一个目标默认一项任务

2026-10-25。负责人反馈一句完善科研项目的要求生成了七项任务。旧流程把模型的每个proposedItem都通过confirmPlan建立为独立任务，阶段、步骤和任务混用；性格文案并不决定这个映射。

## 当前规则与实际写入

工作台规划默认一项任务。目标已足够表达时，助手直接整理待确认任务，内部步骤写入任务说明；材料和日期可后续补，纯问答仍自然回应。canonical task-decomposition方法与planningPrompt均取消默认按阶段分别建任务的引导。用户自改的联系人档案、私人偏好和旧模板保持，不靠覆盖性格来控制任务数量。

新客户端的一项/多项选择按服务地址、账号、课题组和对话保存。一项为默认；只有直接要求创建多项任务的有限明确表达，或主动点“改为多项任务”，才切多项。普通论文/模型数量、抱怨、引用、疑问和助手自己的建议不切换；这不是通用自然语言数量解析器，复杂表达可以用界面明确选择。

客户端plannerTaskInput将同一分工的多个草案步骤合为一项：保留每步标题、目的、交付、验收与依赖顺序，任务名称使用共同目标，步骤写入goal，交付和验收分别汇总。先核对原图，不用合并隐藏循环、失效引用或重复ID。不同分工、公共Agent/执行预算、资料授权、不同内部日程或超出8k说明容量时阻止自动合并，原草案不删减、不静默改权限/日期。共同日程或仅最终步骤的明确整体截止保留，旧日程冲突需继续调整。

预览和确认使用同一份转换。明确点击或回复确认后，createPlannerTasks先重新读取原草案及版本；若需合并，就沿现有editPlan存为一个proposedItem，再确认该精确版本。当前0.32后台按此一项创建一项真实任务；编辑或确认丢回执时复用原幂等键并读取实际状态。其他窗口改动、切账号/组/对话与迟到结果仍按原规则阻断。不是只把按钮数字改为一。

已确认旧任务按实际数量和日期展示，不合并、不删除、不改历史。旧本机多任务创建意图若仍未确认，不能直接续建多项，须点“读取最新方案”重新核对；若早已成功则只找回真实链接，不再创建。
