## 使用行为

- 建群、邀请只选真人；每群固定一个「群助理」，不可移除，也不进入普通通讯录或成为好友。新建同一事务补齐，旧群由迁移补齐。其他群内智能体退出，历史消息、引用、任务承接记录保留；已有明确授权的任务执行按真人承接权限处理，不再借智能体群成员身份判断。
- 课题组数量只统计真实有效成员关系，排除个人空间。零个不关联、一个自动关联、两个及以上要求选择，默认本人 `members.lab_id` 主课题组，不使用当前切换的空间。无课题组用 SQL NULL。群主可修改归属，列与 JSON 同步，审计并发服务消息；已有 IM 标识不重建。
- 群主退群必须选择已加入的真人继任者。原群主退组后，绑定课题组负责人可改派群主，不因此获得群历史。已在群内的负责人有设置入口；未在群内的负责人目前需通过已知群 ID 调用转移接口，没有新增全组群管理页面。
- 群内只有明确 @ 群助理才调用模型，模型输出严格的 `answer/requests` JSON。只注入平台、选定课题组规则、本群历史/记忆、获准关联任务标题与状态和现有公开成员字段。不注入项目约定、个人规则、偏好或私聊，不允许审批、代执行或直接修改共享资产。
- `notify/ask` 是实名转达，收件人必须仍为本群已加入真人；发起人由原始人类消息和服务端账号确定，不接受模型自带 `from`。每人每群按北京时间每日最多 20 条，本群内按收件人/正文哈希去重 24 小时。通知进入对方个人助理会话，群内卡片区分排队、进入会话、回应、撤回、未送达。「进入会话」不等于设备已收或已读。
- 只有收件人明确引用该通知回复，才在群内回一行「X 已回应」，不转发私聊正文。发起人可撤回未回应通知；权限变化取消未送达项，持久化重试最多三次，失败卡片只说未送达，不猜原因。
- 个人事项只有自己/个人助手时不再自动建群；明确邀请真人协作仍按原任务流程处理。群助理的 `assign` 本批明确拒绝，不替代已有任务邀请和人工确认。

## 代码与契约

共享契约 **0.46.0**、聊天协议 **1.14.0**。新增 8 条 CHAT1 路由（该组共 81 条）：课题组候选、群设置、改课题组、转群主、退群、转达列表、按 ID 读转达、撤回转达。新增 `ChatMessage.noticeId`；`Contact.labId`、`Conversation.labId` 允许 null，群专用 public_agent 不具有执行 capability。OpenAPI 与合成 examples 同步导出。

主要入口：`apps/api/src/group-governance.ts`、`group-notices.ts`、`group-assistant-context.ts`；现有聊天 worker、权限/规则装配、IM 映射和任务邀请 worker 负责接入。`packages/constitution/src/group-assistant.ts` 使用现有 assistant 主体，个人层拒绝、审批拒绝、共享变更仅申请；记录 ACL 仍需逐项判断。客户端在原建群/群成员页面接入选择器、折叠群设置和转达卡片。

旧契约的多助手请求字段暂保留解析，实际发送只允许本群唯一助理；多个 ID 或其他助理返回 `GROUP_AGENT_NOT_ALLOWED`。历史多助手回执只用于读取旧记录，不再均分预算或新建多个运行。不要提前删除历史消息所需的身份与资源校验。

旧客户端不能正确解析 nullable 群助理 capability/labId 和通知字段，**这批需协调客户端与后台升级**；不以伪造课题组/执行能力绕过旧解析器。新设置入口要求 `supports(46)`。没有动日常个人助手 persona、原任务规划协议、模型配置、DSH 文件/PDF预览或本地聊天缓存。

## 迁移与部署边界

新增 `035-group-assistant.sql`，5678 字节，LF，SHA256 `d08d5abcdf6d6b4bd8a835fe2590e5ce0fe264fd00ddffdb8bf4871355e8e8cc`。重建允许空课题组的 chat_contacts、chat_conversations、im_identities、im_conversations；旧个人空间群转 NULL。新增 group_retired_agents、group_governance_events、group_notices 三表；取消旧群智能体尚未完成的聊天轮，不改任务/execution_jobs 的业务状态。

迁移器只在迁移事务外临时关闭外键，事务提交前执行完整 foreign_key_check，失败回滚，finally 恢复外键强制。旧迁移字节/校验记录不修改。新建本地空库实测 35 条迁移、120 张表、外键无错误；这是当前源码的空库基线，不拿它覆盖生产实际表数。部署时应记录生产静止基线并核对仅新增三表。

正式部署仍须另行授权：固定提交与镜像；记录 API/worker 回退镜像和其他六容器；排空 worker、停止 API，做静止一致备份；先在恢复副本迁移两次、逐项检查历史保全和外键，再正式迁移/成对启动。沿用完整 Compose 覆盖链、现网 025 字节兼容 Dockerfile，不改 schema_migrations、Nginx、端口或凭据。

**035 不能只切回旧镜像回退**：旧迁移校验器拒绝未知 035，nullable 群归属和清退状态也不符合旧语义。优先兼容版本前滚修复；需要彻底退回时，停写后恢复升级前的一致备份并接受升级后数据损失，须单独决定。尚未在生产副本执行本批迁移。
