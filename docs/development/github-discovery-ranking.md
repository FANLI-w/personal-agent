# GitHub 发现页与科研推荐排序

2026-10-17，根据用户对“内置能力占据发现页”的反馈实现。`feature/github-discovery-ranking` 接续 PR52 / 72355c7；产品源码 **4376ca8a439f9d4cff6ec92d68738aa1fb869060**。

## 页面与数据分工

- **发现能力**只展示既有社区目录中的 GitHub 来源。内置六份科研助手模板移至**我的 Agent**，保留查看、明确添加、已有助手复用和配置入口；课题组成员/Agent留在课题组能力。
- 发现页默认**推荐**，后面依次为**最热门、最新、文献与阅读、写作与表达、研究设计、图表与可视化、数据与代码、课题协作**。发现页不再使用“全部”作为默认项。
- 已审阅条目和待审阅仓库合并排序，待审阅候选不会被单独放在排序结束之后。若同仓库已有审阅的子技能，不再重复显示整个仓库候选；不同已审阅子技能仍保留各自输入、交付和审阅版本。
- 原人物/Agent公开名片不再混入GitHub发现列表。公开与撤回的数据、授权及API保持；个人名片管理弹窗仍从我的Agent/课题组入口打开，并可管理本人已公开的名片。本页原公开人物卡片上的邀请入口随该卡片移出，群组与联系人接口未改。

### 三种排序的实际含义

| 入口 | 排列依据 |
| --- | --- |
| 推荐 | 本人明确选择的工作方向、关注词及当前账号填写的公开专长；卡片显示匹配理由。相同相关度再参考可用状态、仓库Star和代码更新 |
| 最热门 | 全部匹配的GitHub来源按仓库Star降序，候选与已审阅同列；未知数据排在已知0之后 |
| 最新 | 仓库 `pushedAt` 降序；不把发现时间、审阅日期或同步时间冒充代码更新；未知时间排后 |
| 方向 | 已审阅条目按已有目录分类；候选按名称/介绍中有限的中英文词匹配，仍只标待审阅 |

推荐为本机可解释的词与分类匹配，不声称语义模型、科研质量评价或行为学习已经接通。没有偏好时明确提示设置，优先显示已审阅可安装的文字方法。方向权重40、每个关注词12、每个匹配公开专长8；热度不替代相关度。候选的方向匹配是启发式，可能漏掉或误归类用途，应查看原仓库确认。

偏好最多六个方向、八个2–40字符关键词，通过版本化localStorage按当前账号隔离，仅在用户保存后写入；读到损坏/旧schema或受限存储不会破坏发现页。保存受限时只应用本次会话并显示未持久化说明。不会因为偏好分享私人资料、扩大技能执行或自动安装；本轮没有读取聊天、长期记忆或科研文件来推断兴趣，也不向GitHub/模型发送偏好。偏好尚未跨设备同步。

继续使用既有 `communityCatalog` 只读接口和每日后台同步缓存，无新API、数据库迁移、直接客户端GitHub请求或收费模型调用。Star属于仓库而非单份Skill；未知/过期/失败缓存沿用真实状态提示。安装仍取固定审阅提交，最新上游代码不会自动替换已审阅版本；未审阅/待接入条目没有安装入口。
