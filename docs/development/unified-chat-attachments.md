# 图片与文字统一发送

## 行为

图片选择、粘贴和拖入继续先留在输入框，以可移除的缩略图展示。主发送按钮和Enter使用同一入口；仅有图片也可发送，Shift+Enter仍换行。去掉独立“发送图片”按钮、图片计数说明和常驻识字提示；工具栏移至输入框底部，提取文字及查看结果放入图片操作菜单，模型校对改为明确勾选后使用。

一次点击把文字、图片、引用和原会话一起快照进既有待发队列。先确认原图发送，再处理本轮文字；真人和群聊沿用SDK原图与文字消息，并不把若干SDK写入宣称为一个原子事务或同一气泡。普通本机Agent私聊在原图发出后，本机逐图提取文字，保留图片名称/次序，以一个既有agentFileMessage请求承载全文和用户原问题；不再逐张触发独立默认回复，也不另发一个脱离附件的文字请求。群聊@、显式协作、外部Agent的文字授权与文件限制保持，不新增群图片理解或外部附件转发能力。

这次统一发送不等于新增视觉模型：Agent收到的是标明来源的本机OCR文字，不能声称看到了物体、图表或排版。无文字、识别失败或超限会保留待发记录，不编造回答。新旧文件阅读的权限、解析、预算和覆盖范围仍由既有后台处理。

## 恢复与边界

每张图片保存SDK原消息标识及真实回执。重试跳过已确认原图，未确认的图片复用原SDK消息；OCR中途失败保留已提取部分，最后的文件请求保留原正文和幂等键。前一条失败会阻止后续队列自动越过。切换聊天或账号会停止旧操作，晚到回执不会向新会话续发。

原图File对象和中间OCR仅在当前账号内存队列保存，不编码写入sessionStorage；本地恢复只保留文件名、大小、标识和已生成的读取请求。刷新后缺少必要原图时明确要求核对聊天记录并重新选图，不降级成只发文字；已经确认全部图片且已生成读取请求的记录可核对原请求。退出/换账号清理旧队列。输入托盘和整批待发图片受20张/单张10MiB/总50MiB约束，整份提取文字仍受既有10MiB文件上限，不截断原问题或OCR。
