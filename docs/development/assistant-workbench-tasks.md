# 科研分工、个人助手与工作台任务衔接

2026-10-18（北京时间）。`release/acceptcat-0.10.14` 接续 PR63 / `9b32c56`，产品源码 `6d643df393b91ce9f5a5c6d3bfb6b6d6a173d3fb`。客户端复用现有 contract0.25 以内接口，没有新 API、数据库迁移或后台部署依赖。安装包事实另见[0.10.14交付](../deployment/acceptcat-0.10.14.md)。

## 从科研目标到真实分工

工作台“我的任务”主动作改为“安排科研任务”，进入原科研计划编辑；“联系人协作任务”保留为独立入口。前者以课题组科研步骤、成员承接与成果审阅为主，后者沿用本人获准联系人的协作草案/群邀请，不把两者的成员关系混为一谈。

计划草案增加“统一安排负责人 / 应用到全部步骤”，可明确选择自己、同组成员或待成员认领。只改草案，保留每步 ID、依赖、时间与输入资料；邀请要在确认创建后发送，本人接受才形成承接。单步仍可分别调整；待认领也有可读选项和实际 claim allocation，不再显示无法操作的原始值。批量入口不自动为全部步骤分派公共 Agent 或增加模型预算。

确认前逐步预览名称、拟分工、交付及截止；未填或待确认日期明确保留。长清单可滚动，确认窗口居中适配窄桌面。最终保存、版本核对、任务创建、权限、依赖与验收仍由原服务处理。

## 同一项任务可以来回找到

- 统一任务详情链接区分 `taskKind=research|personal`，旧无类型个人任务链接兼容。未知类型/非法 ID 显示无效，不猜另一套接口。任务列表点击后写入真实 taskId 与类型；书签重开可直接读取，科研任务不会误送到个人协作接口。
- 已确认计划的具体步骤、团队总览操作与成员下一步，都可打开同一个工作台任务；保留快速预览。发起人在完整科研任务里可返回自己所属计划，其他成员不展示私人计划入口。服务端继续校验实际访问权限。
- 总览增加“我的待办与助手安排”；个人助理聊天标题提供“工作台任务”抽屉，读取同一份实际工作台聚合。按待处理/进行中切换，最近三项及完整列表入口明确，不把模型回答当成已完成任务。
- 委派回执可“打开对应工作台任务”：点击后读取当前获准工作台页，按真实 conversationId 与执行 turnId 精确匹配，再打开。不会按 Agent 名称、标题或“同一个聊天”猜测。兼容既有后台已持久保存但未在回执中直接给出 taskId 的记录；最多读取最近1000项，找不到或读失败明确说明。取消、页面/账号切换中止读取并阻断迟到导航。
- 有真实来源对话的完整个人协作任务提供“返回需求对话”，与“返回任务聊天”分别保留；先核对服务端当前权限及真实 IM 映射。没有连接时保留任务并显示失败，不声称已打开或已送达。两者为同一对话时不重复显示来源按钮。
- 助手的科研协作建议也可打开准确计划/任务。联系人任务预选 Agent 时同时加入其草案成员；移除成员时清除相应预选，修复客户端可提交不符合原 API 条件的组合。创建个人任务后清除旧科研任务类型，避免从科研详情新建时误读另一接口。
