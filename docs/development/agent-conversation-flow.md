# 从交流到成果的科研助手调整

2026-10-24。负责人要求整体检查任务流程和各 Agent 设计，使其更体贴、自然、有科研判断。本批以源码逐段核对现有入口和状态流转，不把源码检查称为界面实测或真实模型质量验收。

## 统一的交流原则

先用已知信息帮忙，再决定是否问。确需澄清时，每轮最多一个简单、必要的问题，不能把多个要求藏进一个句子。可推迟的信息保留未知，已经给出的信息继续使用。用户烦躁、疲惫或不知如何选择时，主动提供一个小切入口。

方法要求由助手承担：整理目标、证据、实验比较、分析设计和检查项，不把整套方法变成用户必须先填写的表。短问题直接回答；需要完整方案、严格审稿或深入分析时充分展开，不机械限制回复长度。结论严格，语气尊重；批评证据与论证并给修法，不评判作者能力。

## 逐段核对和修改

| 流程 / 设计 | 发现的问题与本批处理 |
| --- | --- |
| 规划开场与方案 | 保留上一批对话优先，进一步要求从最小有用阶段开始；后端规划规则对齐，零步骤交流草案沿现有Plan结构；多个创建问题按首项/展开详情呈现，全部校验保留 |
| 个人助理与日常聊天 | 共用紧凑交流规则，优先当前问题和已有上下文；普通研究讨论直接回复，只有实际需要专门分工时才委派；原上下文选择、记忆权限和已确认任务事实继续使用 |
| 任务创建与成员承接 | 提示解释会发生什么、谁来决定；邀请不当作接受，草案不当作执行授权；版本、幂等、取消与正式确认机制保持 |
| 执行和阻碍 | 下一步按当前查看者区分承接人、审阅人、支持成员和其他成员；显示需要的帮助，避免对所有人使用同一催办指令；不改变 allowedActions 或读取范围 |
| 交付和审阅 | 引导说明真实结果和未解决问题；审阅强调达到的要求和关键修改建议；结果不支持假设也能如实记录，提交不当作验收 |
| 七个内置助手 | 文献、改稿、研究方案、图表、数据复现、组会、资料模板开场改为自然切入口，新增交流偏好；保留全部原能力边界。旧模板继续识别复用，用户自改档案不自动覆盖 |
| 资料 / 附件 / Skill聊天 | 回答当前问题，按证据使用来源；空片段给具体检索建议；方法按需展开，无工具的阶段给可用文本替代，不冒称搜索、执行或保存文件 |
| 十一个canonical Skills | 对选题、创新性、实验、循环研究、检索、综述、统计、阅读审稿、写作、ICLR检查和拆解逐项调整；正式证据/执行 gate 保留，探索讨论不要求先凑齐完整材料包 |
| 状态、失败与恢复 | 简短说明实际状态和一个可操作下一步；预算不足不要求检查整套配置，不自动加预算；模型格式/服务失败不责备用户，安全未知结果仍按原操作恢复 |
| 提醒、记忆和外部Agent | 提醒/记忆解析失败给简短纠正方式；外部当条请求携带同一交流原则，权限、逐条授权与私密材料隔离保持 |

桌面和后台分别生效。规划prompt/模板/界面随安装包使用；日常聊天、委派、创建、资料/Skill及外部系统规则的修改在后台源码，需要另行部署后才对线上生效。内置方法包的文件变化不等于已修改已安装的私人Skill版本。

## 保留的边界和评价方式

不增加工具、自动执行、共享或通知权限，不改变API、契约、数据库或依赖锁。不伪造进展、阅读范围、引用、实验和验收。原件权限、私库范围、任务确认、资源预算及第三方实际行为仍受原机制约束。定时命令仍是有界完整表达解析，不能声称已实现提醒的多轮槽位对话；已确认计划的对话式修改、跨设备规划历史也不是本批新功能。

合成情境见[评价场景](../../evaluations/fixtures/agent-conversation-flow.md)。检查覆盖角色化提示、旧模板复用/账号隔离、原确认/取消/版本、预算、历史与材料完整性；语言要求不能只靠字符串或替身模型证明。安装、界面、真实用户材料和真实模型效果由负责人按既有安排检查，实际运行回执见current-state和本批交付记录。
