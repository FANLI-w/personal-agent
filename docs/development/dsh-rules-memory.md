# DSH 第二步：规则、交接、记忆与工作索引

2026-10-28。负责人批准实施三步计划第二步。分支 `feat/dsh-rules-memory` 从实际 main/93da480 建立并保留第一步 PR131/db9086e 依赖；原共享开发目录不动。候选客户端 0.10.69。第三步的多设备领取、多 Agent 协作不在此批。

## 使用方式

任务工作页增加“规则与记忆”。不要求先填写规则才能使用。

- 平台规则随产品版本发布；真正的账号、资料、任务与工具权限继续由业务接口和 DSH 执行条件检查，不能靠提示词授予。
- 科研任务继承所在课题组和项目规则。首版“项目”对应既有研究计划 planId，项目负责人为计划创建者；课题组负责人沿用现有 lab manager。负责人保存即发布，成员只能提出候选；确认/纠正/撤回保留逐版内容、操作者与时间。
- 项目记忆属于有来源任务的短结论。只有同时有权访问当前项目任务和来源任务的人能够读取其正文及版本历史。模型推断不会自动变成已确认的团队共识。
- 个人记忆继续使用原有确认/纠正/撤回 API 和 PersonalMemoryPanel。只有本人持有、没有其他人或他人的 Agent 参与的个人任务可以显式开启；科研团队任务、共享个人任务均不能读取私人记忆。
- 本次要求仍写在执行输入框，只用于本轮，不自动变永久规则。

### 交接与换会话

执行结束后核对“结论、证据、下一步、阻碍”并确认保存，首版摘要正文不超过 4KB。记录原 DSH 会话与序列位置、已选来源版本/哈希、前20个可读输出的 SHA256；这是可核对的执行证据，不是验收完成。每任务保留100版摘要和50个历史会话，达到上限明确提示。

“保留历史，换一个执行会话”会创建真正的新 DSH 会话，保留原工作目录与历史，并在下一次工作请求带入当前有效交接。交接先按账号和设备保存在本机；要成为团队项目记忆，需要有权的人明确发布。

当前规则、任务要求、启用的个人记忆或选定方法版本变化后，下次执行自动使用新会话，防止旧值留在模型历史中。旧交接与当前规则指纹不一致时不自动注入，需重新核对确认。原始历史保留供用户查阅，不宣称撤回能抹去已执行的工具影响或模型提供方已收到的内容。

不确定请求持久保存原始上下文和请求ID。重试不会变成一次新操作；其依据已撤回时阻止重放。用户核对原会话、结束运行后，可以明确放弃待确认请求并换会话；已执行动作不会自动撤销。

### 按需上下文与索引

工作索引将当前任务、来源版本、工作目录文件、交接和 DSH 历史关联起来，搜索当前授权的规则/记忆正文与本机条目名称。首次不建立全团队向量库，不扫描用户其他工作目录。跨项目检索与多设备索引属于后续能力。

每次发送重新读取服务端规则和实际权限，不使用离线旧规则冒充当前生效值。规则/摘要更新不会同步修改旧会话。普通问候不追加任务档案、交接、个人记忆、资料清单或 Skill 正文；同一会话已经存在的历史以及 DSH 自身系统提示/工具定义仍可能占用上下文，不能承诺问候零成本。

内置方法仍来自 `agents/skills` 的打包产物，复用 research-skills 解析器。每任务最多显式选择2个 Skill；只把所选正文加入工作请求，其引用文件以版本化副本放在任务目录 `.acceptcat-methods` 下供工具按需读取。不运行打包脚本，不自动安装第三方插件或复制整套方法正文。被用户改动的版本副本报错，不静默覆盖。

“最近一轮上下文依据”展示实际送入的条目与版本、未载入条目、发送字节数及粗估 tokens。此值只衡量 AcceptCat 增补，不是 DSH 全部上下文或实际计费。规则合计超过12KB会报错要求精简；任务/摘要/可选方法分层使用总计约36KB的增补预算，可选项超限会列明省略原因，不截断规则冒充完整执行。

## 技术与部署

固定 DSH 0.2.1-rc.3、Electron22.3.27不变，沿用官方 workspace/session Remote RPC。没有修改上游 DSH 源码，模型Key依旧留在既有后台。

- 新增 contract0.36.0 的 `workContext`、`saveWorkRule`、`workRuleHistory`，沿用 Cookie、CSRF、同源、幂等和版本冲突处理。编辑权限来自服务器，不由客户端提交负责人身份。
- 新增迁移029：`work_context_records`、`work_context_revisions`，与旧任务、记忆和资料表分开，保留唯一事实来源；没有后台自动执行或模型费用。
- 本机 DSH 适配器负责检查点、新会话、上下文选择回执及版本化方法副本。账号更换仍由现有 lease 使旧请求失效。
- 新客户端执行任务需要配套上下文接口。旧后台返回不可用时明确报错，不静默绕过规则。独立 DSH 页和原聊天接口保持原路径。

**本批没有部署后台。** 上次记录生产为 f58bf538/contract0.34/schema027；主线已有028而未部署。部署前必须重新核对实际生产基线，审阅028与029的整套迁移及API/worker配对版本，停写备份并在独立库演练恢复，再由负责人安排上线。不能只把新API文件覆盖到旧生产库。保留旧表不等于旧程序会接受新schema：当前旧程序严格检查迁移历史，不可直接降级挂载已迁移库；优先前滚修复，若必须回退，单独设计新写入数据的保全与重放，不回灌旧库覆盖新工作。
